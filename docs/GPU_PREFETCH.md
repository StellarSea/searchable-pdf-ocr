# GPU 요청 선행 준비

자동 CLI는 CPU가 이미 준비한 줄 PNG를 언어별로 묶어 GPU에 미리 보낸다.
이미지/모델/입력 폭/줄 분할 임계값은 바꾸지 않는다. GPU 모델 작업자 수는 1,
서버의 실제 추론 배치 크기는 32 그대로다. GPU 사용률 100%를 강제하는 기능은 아니다.

## 범위와 복구

- `ocr_gpu_prefetch.GPUPrefetch`가 문단·페이지를 넘는 줄 이미지를 최대 64개씩 묶는다.
  같은 모델의 동일 이미지 키는 중복 전송하지 않고, 기존 캐시 응답을 우선한다.
- 선행 요청은 최대 2개(실행/대기 포함), PNG·base64·JSON 전송 여유를 포함한 예산은 64 MiB다.
  한 이미지가 예산보다 크면 축소하지 않고 원래 문단별 경로에 맡긴다.
- 기존 HTTP 스레드 1개만 사용한다. PDF/폰트/SQLite는 소유 스레드에만 둔다.
  CPU의 완료 결과 회수 시점에 요청을 보충하고, GPU를 기다리는 동안에도 CPU 준비를 보충한다.
- 응답 개수·문자열 형식을 검사한 후에만 캐시에 저장한다. PDF 삽입과 배치 결정은
  원래 페이지·문단 순서대로 수행하며 최종 감사 기록 게시 규칙도 유지한다.
- 선행 요청이 실패하면 같은 실행에서 선행 공급을 해제하고 기존 문단별 인식으로 복구한다.
  선행 기능 자체는 서비스를 재시작하지 않는다. 이미 저장된 정상 응답은 중단 후에도 재사용한다.
- 완전한 캐시 재실행에서는 GPU 요청을 하지 않는다.

기본 명령은 그대로다. `--no-gpu-prefetch`를 추가하면 이 기능만 끈다.
`--no-prefetch`는 HTTP 겹치기를 해제하므로 GPU 선행 요청도 꺼진다.
CPU 준비를 끄거나 준비된 PNG가 없는 페이지는 기존 문단별 경로를 사용한다.
라이브러리 `overlay()`는 호환성을 위해 `gpu_prefetch=False`가 기본이며 CLI가 활성화한다.
옵션은 완료/캐시 식별자에 영향을 주지 않는다. 이미 실행 중인 작업에는 소급 적용되지 않는다.

보고서의 `gpu_feed_stats`에는 요청·이미지 수, 완료 요청 수, 최대 큐·보관 예산,
소비 시 대기 시간 및 복구 이유를 기록한다. 정확도 판정과 분리된 성능 통계다.

## 실제 이미지 요청 비교

2026-09-13 실제 한글/영문 24문단, 119개 줄 PNG를 사용했다. 준비된 PNG의 요청/응답만
측정하며 PDF 렌더링·전체 OCR 시간은 아니다. 모델 예열은 제외하고 실행 순서를 회전해 3회 비교했다.

| 요청 방식 | 요청 수 | 중앙값 |
|---|---:|---:|
| 기존 문단별 | 24 | 3.669초 |
| 32개씩 묶기 | 5 | 1.885초 |
| 64개씩 묶기 | 3 | 1.718초 |

64개 방식은 이 표본의 요청 시간에서 약 53.2% 단축했다. 모든 인식 문자열이 같았다.
모델 신뢰도 점수는 최대 약 0.000373 달랐으며 현재 클라이언트는 이 점수를 사용하지 않는다.
표본 밖의 모든 입력에 같은 문자열/속도를 보장하지 않는다. 원시 결과는
`tmp/gpu_feed/request_comparison.json`, 재현 도구는 `tools/benchmark_gpu_feed.py`다.

`tests/test_ocr_gpu_prefetch.py`는 문단 묶기 전후 PNG 해시/결정/문자/좌표/픽셀,
언어별 분리·큐/메모리 상한·소유 스레드·잘못된 응답 복구·캐시 재실행을 확인한다.
`tools/benchmark_gpu_overlay.py`는 CPU16 조건을 고정하고 실제 책 표본의 전체 overlay를 비교한다.

## 실제 책 32페이지 overlay 비교

2026-09-13 목차 6·7페이지와 29페이지 등을 포함한 32페이지에서 CPU 작업자 16개를
고정하고, 각 방식에 별도 빈 진단 캐시를 사용해 한 쌍을 비교했다. 원본과 운영 캐시는 변경하지 않았다.

| 측정 | 기존 문단별 | GPU 선행 공급 |
|---|---:|---:|
| overlay | 41.87초 | 30.95초 |
| 최종 검증 포함 | 57.76초 | 47.91초 |
| HTTP 요청 | 133회 | 30회 |
| 전송 줄 이미지 | 771개 | 771개 |
| 최대 측정 RSS | 4.61 GiB | 5.00 GiB |

이 표본에서 overlay 시간은 약 26.1%, 검증 포함 시간은 약 17.1% 단축했다.
인식 후보·이미지 키·배치 결정·글자/좌표·렌더링 픽셀·성능 통계를 제외한 품질 보고서는 같았다.
캐시 재실행에서도 같은 결과였으며 GPU 요청과 CPU 풀 시작이 모두 0회였다.
선행 공급 오류는 없었고 최대 선행 보관 예산은 66,961,516바이트로 64 MiB 이하였다.
전체 책이나 다른 문서의 속도/정확도 보장 또는 GPU 사용률 100% 달성을 뜻하지 않는다.
원시 결과는 `tmp/gpu_feed/overlay32/comparison.json`에 보관했다.

오프라인 전체 테스트 140개를 통과했다. 실제 요청 비교 후 기본 묶음 크기를 64개로
확정한 뒤 GPU 선행 공급 테스트 5개를 다시 통과했고, 정적 구조 검사도 통과했다.
