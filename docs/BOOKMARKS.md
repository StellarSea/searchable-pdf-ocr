# 자동 책갈피

## 새 OCR 변환

```powershell
python run.py "input/book.pdf" --out output --bookmarks
python run.py input --recursive --bookmarks
```

선택 기능이다. 기존 `--toc` / `--toc-all`은 유지하며 함께 지정하면 `--bookmarks`가 우선한다.
원본에 있던 사용자 책갈피는 보존한다. OCR 모델·해상도·원시 캐시·본문 글자·배치는 변경하지 않는다.

## 이미 변환된 PDF의 책갈피만 갱신

```powershell
python run.py bookmarks "input/ocr_output/신호 및 시스템_auto_searchable.pdf"
python run.py bookmarks "input/ocr_output"
```

OCR 서버 없이 기존 완성 PDF와 게시된 OCR 레이아웃을 사용한다. 해당 책의 SQLite 보고서와
원본 PDF가 필요하다. 원본 SHA-256과 레이아웃 해시를 검증하고 문서 출력 잠금을 획득한다.

이전에 프로그램이 만든 책갈피는 이전 보고서의 제목·계층·목적지와 정확히 같을 때만 교체한다.
사용자가 수정한 책갈피가 발견되면 중단한다. 프로그램 생성 이력이 없는 사용자 책갈피는 그대로 보존한다.
갱신을 반복해도 항목을 중복 추가하지 않는다.

기존 PDF와 보고서는 `.ocr/bookmark_history/책이름/실행시각_고유번호/` 아래에 보존한다.
후보 PDF는 기존 PDF를 복사한 뒤 책갈피 변경만 증분 저장한다. **모든 페이지**를 검사한 후 교체한다.

- 기존 책갈피 객체와 카탈로그의 Outlines 참조 외의 기존 PDF 객체·스트림이 동일한지 확인
- 전 페이지 추출 문자·글자 좌표·페이지 회전·cropbox·mediabox 비교
- 전 페이지 72dpi 렌더링 픽셀 비교
- 저장 후 책갈피의 Unicode 제목·계층·실제 목적지 좌표 재확인
- 검증 중 입력 PDF가 변경되지 않았는지 해시 확인

검증 실패 시 기존 완성 PDF와 성공 보고서를 유지한다. 실패한 후보와 백업도 삭제하지 않는다.
새 JSON/Markdown 보고서와 완료 상태는 검증된 PDF 게시 후 기록한다.

Windows 파일 잠금 등으로 마지막 교체만 실패하면 검증된 후보는 history에 남는다.
PDF 뷰어를 닫고 `python run.py bookmarks --publish-verified "history 폴더 경로"`로 재시도한다.
검사 당시의 원본·기존 PDF·백업·후보·보고서가 그대로인지 확인하고 교체하므로 전체 렌더링은 반복하지 않는다.

## 인식 방식

1. `차례`, `목차`, `Contents`, `C O N T E N T S` 같은 표제와 제목/쪽수 패턴을 찾는다.
   쪽수가 별도 줄 또는 별도 블록에 있는 목차, 여러 페이지에 이어지는 목차, 단순 HTML 표를 읽는다.
2. 쪽수가 없는 장 제목도 독립 항목으로 보존한다. 장 제목과 다음 절을 이어 붙이지 않는다.
   제목·쪽수가 모두 남아 있지 않은 항목도 후보에 남겨 누락을 추적한다.
3. 본문에서 인쇄 쪽수를 별도로 읽고 해당 페이지의 제목을 대조한다. 같은 책의 모든 페이지에
   하나의 고정 보정값을 적용하지 않는다. 원본 페이지 누락으로 쪽수 차이가 바뀌어도 처리한다.
4. 장 첫머리의 단원 개요/학습목표와 반복된 절 목록을 구분한다. 장은 소개 페이지로,
   절은 실제 본문 제목으로 연결한다. 떨어진 절 번호와 제목은 인접 배치를 확인하여 묶는다.
5. 장식 글머리표와 `연 / 습 / 문 / 제` 같은 표기를 비교용으로 정규화한다.
   OCR 오독에 대한 유사도 비교는 인쇄 쪽수 등으로 위치가 확인된 페이지의 제목에만 허용한다.
   다른 숫자·수식 기호는 임의로 같다고 취급하지 않는다. z-변환 관련 2/z 혼동은 제한적으로 비교한다.
6. 같은 제목이 여러 곳이면 제목 분류, 쪽수, 장 범위, 앞뒤 항목으로 구별한다.
   확인할 수 없는 항목은 검토 목록에 남긴다. 실제 페이지가 누락된 경우 목적지를 만들지 않는다.
7. 목차가 없는 문서는 명시적인 번호가 있는 본문 제목만 사용한다. 장 소개와 번호 달린 연습문제는 제외한다.

## 원본 이미지를 확인한 책갈피 교정

OCR 오타가 목차 제목 자체에 있으면 별도 교정 파일을 사용할 수 있다. 교정은 책갈피에만 적용되며
OCR 본문·원시 레이아웃을 수정하지 않는다.

```powershell
python run.py bookmarks "input/ocr_output/신호 및 시스템_auto_searchable.pdf" --review "reviews/bookmarks/signals.json"
python run.py bookmarks "input/ocr_output/쉽게 배우는 C 자료구조_auto_searchable.pdf" --review "reviews/bookmarks/cdata.json"
```

교정 파일에는 원본 `source_sha256`, 게시 레이아웃의 `layout_sha256`, `corrections` 목록을 둔다.
각 항목은 `toc_page`와 정확한 `original_title`로 대응하고, 수정할 `title` 또는 `printed_page`,
원본 확인 근거 `reason`을 기록한다. 원본/레이아웃이 달라졌거나 항목이 유일하게 대응하지 않으면 거부한다.
같은 목차 페이지에 동일한 제목이 반복되면 선택자 `chapter`를 함께 지정하여 장 범위를 구별한다.
교정한 표시 제목과 원래 OCR 표기는 함께 보존하여 목적지 대조에 사용한다.

책갈피 전용 갱신은 성공한 보고서에 교정 파일 경로를 보관하므로 다음 갱신에도 자동 재사용한다.
OCR 변환 자체를 다시 실행할 때는 `--bookmarks --bookmark-review 교정.json`을 명시해야 한다.
교정 파일은 특정 원본과 레이아웃에만 유효하다.

v3는 쪽수가 없는 장별 contents 패널과 전체 목차를 구별하고, 인쇄 쪽수 열이
누락된 연속 목차 페이지를 유지한다. 장 표지의 절 목록은 본문 절 목적지에서 제외하며,
양쪽 목차 페이지 사이에서 contents 레이블과 절 번호가 충분한 경우에만 손상된 중간 페이지를 연결한다.
실제 본문 절 제목과 학습목표가 함께 있는 페이지는 장 표지로 오인하지 않는다.
반복된 다음 페이지 제목보다 장 표지를 우선한다. 부록 A/B와 A.1/B.1 계층도 지원한다.
OCR이 제목을 짧게 오독하여 자동 대조가 불가능하면, **원본 이미지로 확인한 경우에만**
교정 항목에 `destination_page`(1부터 시작하는 PDF 페이지)와 `destination_text`
(해당 페이지의 정확한 OCR 제목 문자열)를 함께 지정할 수 있다. 원본/레이아웃 해시와
유일한 제목 후보를 모두 검증하며, 기존 `reason` 확인 근거도 필수다. 제목이 달라졌거나
동일한 후보가 둘 이상이면 적용을 거부한다. OCR 원문은 변경하지 않는다.

## 결과와 정확도 범위

위 예제의 `reviews/` 자료는 특정 원본에 묶인 로컬 교정으로 공개 저장소에 포함하지 않는다.
외부 사용자는 자신의 원본과 레이아웃 해시에 맞춰 직접 검토 자료를 작성한다.

기존 보고서의 `bookmarks`에 목차 페이지, 전체 후보 수, 확정 항목, 보류 이유, 적용한 교정,
실제 이동 좌표와 저장 후 검증 결과를 기록한다. `bookmark_refresh`에는 갱신 전후 해시,
백업 위치와 전체 보존 검사 결과를 기록한다. 원시 OCR 응답과 원시 캐시 항목은 그대로 유지한다.

`source_page_missing`은 인접한 실제 PDF 페이지의 인쇄 쪽수가 건너뛰어 해당 페이지가 없는 경우다.
`title_not_found`, `ambiguous_title`, `destination_out_of_order` 등은 자동으로 확정하지 않은 이유다.

`verified`는 PDF에 계획대로 저장됐다는 뜻이며 OCR 자체의 정답률 보증은 아니다.
복잡한 목차·심한 오독·불완전한 원본까지 무조건 복원하지 않는다. 원본에 없는 내용을 만들어 넣지 않는다.
실제 두 책에 대한 검사 범위와 결과는 [검증 기록](BOOKMARKS_VALIDATION_20260916.md)에 정리한다.
