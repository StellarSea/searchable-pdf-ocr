# GPU 줄 인식 작업자 수 측정

2026-09-13, RTX 5080 16GB. 기본 작업자 수를 **4 → 1**로 조정했다.
현재 클라이언트의 작은 블록별 순차 요청에서는 GPU 작업자를 늘려도 빨라지지 않았다.
1개 작업자도 배치 추론을 하며, 한 줄씩 모델을 새로 만드는 방식이 아니다.

## 방법

- 실제 책의 기존 overlay 보고서 좌표로 RGB 줄 이미지를 생성했다. 해상도·여백·모델·입력 폭 320·배치 크기 32·CPU 스레드 8을 유지했다.
- 표본 A: 12페이지, 12블록, 한글 모델 35줄 / 기본 모델 17줄, 총 52줄.
- 별도 표본 B: A와 겹치지 않는 12페이지, 12블록, 한글 모델 36줄 / 기본 모델 31줄, 총 67줄.
- 작업자마다 새 격리 컨테이너를 사용하고, 각 사례를 예열한 뒤 3회 측정한 중앙값을 사용했다.
- A는 1·2·4·6·8개, 2·4개 재측정도 수행했다. B는 1·2·4개로 확인했다.
- 문단 OCR 서버는 유지했고, 줄 인식 운영 서버만 측정 중 잠시 중지했다.
- 각 블록의 중앙값을 합산했다. 다음 값은 줄 분할과 모델 추론만 포함한다. HTTP·PNG 디코딩·PDF 렌더링·overlay·최종 검증은 제외한다.

## 결과

| 작업자 | A: 52줄 처리 | B: 67줄 처리 |
|---|---:|---:|
| 1 | 1.106초 | 0.737초 |
| 2 | 1.061초 / 재측정 1.050초 | 0.863초 |
| 4 | 1.452초 / 재측정 1.267초 | 1.172초 |
| 6 | 1.515초 | 미측정 |
| 8 | 1.501초 | 미측정 |

4개 재측정 값을 기준으로 두 표본 합계는 2.439초 → 1.843초로 약 24% 단축됐다.
GPU 모델 추론 구간의 합계는 약 1.115초 → 0.416초였다.
1개와 2개의 우열은 표본에 따라 달랐지만, 합계와 추론 구간은 1개가 가장 빨랐다.
이는 현재 작은 블록 요청에서 병렬 분배 비용이 이득보다 크다는 해석과 일치한다.
책 전체 처리시간이 24% 단축된다는 의미는 아니다.

같은 모델의 줄을 합친 큰 요청도 별도로 검사했다. 두 표본의 큰 요청 시간 합계는
1개 1.634초, 2개 1.604초, 4개 1.787초였다. 향후 페이지 단위 요청으로 바꾸면 재측정해야 한다.

인식된 문자열과 순서는 모든 비교에서 4개 작업자 기준과 같았고, 반복 측정 중에도 변화가 없었다.
이것은 **119개 실제 줄 표본의 결과 유지 검사**이지, 사람이 정답을 붙인 정확도 평가가 아니다.
운영 서버에도 1개 작업자를 적용하고 HTTP 요청으로 119줄을 다시 확인했으며,
4개 작업자 기준과 문자열·순서가 모두 같았다. 전체 회귀 테스트 77개도 통과했다.

GPU 전체 메모리 사용량도 0.2초 간격으로 측정했다. 다른 GPU 프로그램과 WDDM의 영향으로
4개 작업자 재측정 자체도 변동했으므로, 작업자당 메모리 절감량을 확정하지 않는다.
관측된 최대 사용량은 약 13.8~14.5GB였고 측정 중 메모리 부족 오류는 없었다.

## 적용 및 재현

`compose/compose.yaml`과 `compose/line_ocr_server.py`의 기본값은 1이다.
`LINE_OCR_WORKERS`로 재설정할 수 있다. 환경 변수를 바꾼 뒤에는 단순 restart가 아니라
`docker compose up -d --no-deps paddleocr-line-api`로 컨테이너 설정을 반영해야 한다.
`/health`가 실제 작업자 수·입력 폭·배치 크기를 보고하며, 응답 timing의 `workersUsed`는
해당 요청에 분배한 작업자 수를 보여준다.

인식 모델과 입력은 변경하지 않았으므로 기존 이미지 캐시 및 수동 검토 키를 보존했다.
클라이언트 캐시 이름의 `w4`는 과거 네임스페이스이며 현재 서버 작업자 수를 뜻하지 않는다.

재현 도구:

- `tools/prepare_worker_benchmark.py`: 기존 보고서 좌표에서 표본 생성.
- `tools/benchmark_line_workers.py`: 운영 캐시를 사용하지 않는 격리 측정.
- `tools/summarize_worker_benchmark.py`: 결과·문자열 차이 집계.
- `tools/verify_worker_service.py`: 적용된 HTTP 서버의 설정과 문자열 일치 검사.

원시 결과는 `tmp/gpu_workers/w*.json`, 추가 표본은 `tmp/gpu_workers/holdout/w*.json`에 남겼다.
각 폴더의 `summary.json`에 비교 요약이 있다. 실제 입력 이미지도 보존되어 있다.
