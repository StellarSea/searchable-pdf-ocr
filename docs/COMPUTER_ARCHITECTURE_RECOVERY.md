# 컴퓨터 구조론 PDF 저장 검증 실패 수정 (2026-09-20)

## 원인

2026-09-18 실행은 OCR 후 564페이지 검증에서 중단됐다. 실패 보고서는 책별
SQLite의 `컴퓨터 구조론_auto_failed_report.json`에 있으며, 실패 페이지는
36, 240, 290, 302, 394, 470, 548이다.

- 36, 240, 302, 394, 470, 548: 작은 블록에 4,096~6,724자의 OCR 결과가 있었다.
  줄 탐지 결과가 없어 문단 배치를 사용했고, textbox에 들어가지 않자 기존
  예외 경로가 고정 3pt 크기의 한 줄을 삽입했다. 페이지 밖으로 넘친 문자가
  추출되지 않아 `extracted_text_mismatch`가 발생했다.
- 290: 파생 경계 캐시의 `[无法识别]` 중 `识`, `别`이 기본 맑은 고딕에 없었다.
  문단 경로는 대체 폰트를 사용하지 않아 두 글자가 NUL로 저장됐다.

36·290페이지 원본의 해당 위치는 머리말의 장식 그림이다. 반복 수식이나
`[无法识别]`은 실제 책 내용으로 확인된 문구가 아니다. 이 수정은 저장의
문자 보존 오류를 고치는 것으로, OCR 오인식을 정답으로 인정하거나 교정하지 않는다.

## 수정

`ocr_fonts.insert_invisible_paragraph`가 기존 textbox 배치를 유지하면서,
넘침 또는 누락 글리프가 있을 때 기존 글리프별 대체 폰트 선택을 이용한다.
이 경우 상자 너비와 폰트의 ascender/descender에 맞춰 텍스트를 축소한다.
회전/cropbox 변환과 투명 텍스트 조건을 유지하며, 일반 줄 배치의 동작은 바꾸지 않는다.
해당 페이지에는 `paragraph_compacted` 검토 경고를 추가한다.

원시 OCR/파생 경계 캐시, 모델, 렌더링 해상도, 탐지 임계값, 캐시 키,
최종 검증 기준은 변경하지 않았다. 검증을 통과한 뒤에만 최종 PDF를 게시한다.

## 검증과 복구

- 기존 실패를 재현한 뒤 긴 반복 문자열과 CJK 대체 폰트 회귀를 추가했다.
  0/90/180/270도 회전과 cropbox에서 문자 순서·상자·픽셀·투명성을 확인하고,
  PyMuPDF와 pypdf 양쪽에서 저장 후 원문 추출을 검사했다.
- 일반 문단의 PDF 내용 스트림과 글자 좌표가 기존 textbox와 동일함을 검사했다.
- 전체 오프라인 308개 통과(196.881초). 마지막에 추가한 일반 문단 검사까지
  포함한 문단 회귀 3개도 통과했다. 구조 검사도 통과했다.
- 캐시 전용 복구는 97.7초에 완료됐다. 564페이지 전체 원본 픽셀·문자·투명성
  검증을 통과했다. 새 OCR 요청 0회, 서비스 시작/재시작 0회다.
- 실패했던 7페이지 모두 기대 문자 수와 일치하며 NUL이 없다.
  나머지 557페이지는 이전 부분 PDF와 문자·글리프 위치가 동일하다.
- 원시 OCR와 줄 인식 응답 해시가 동일하다. 별도로 경계 페이지 체크포인트와
  실패 보고서 등 1,122개 기존 항목의 바이트 해시도 동일함을 확인했다.
- 36·290페이지를 렌더링해 원본/결과 화면을 직접 비교했다.

결과는 `input/ocr_output/컴퓨터 구조론_auto_searchable.pdf`다.
완료 상태는 `completed_with_warnings`이며 검토 대상은 557페이지다.
검토 경고는 오답 페이지 수가 아니고, 원문과의 완전한 인식 정확도 보장도 아니다.
특히 위 반복 숫자·수식과 인식 불가 문구는 후속 원본 대조 교정 대상이다.

실패 당시 SQLite와 부분 PDF는
`tmp/computer-architecture-recovery/before-20260920/`에 보존했다.
복구 스크립트, 로그, 검증 요약과 비교 PNG는 같은 상위 폴더에 있다.
